# Shared combat calculator

`src/Calculator.tsx` exports the React component used by the standalone page
and the Scryglass calculator tab. Hosts import `src/calculator.css` once.
The component inherits Scryglass color and font variables. All its styles use
the `calculator-` prefix.

The `apiBase` prop prefixes the existing backend routes. An empty value calls
`/api/config`; `/api/calculator` calls `/api/calculator/api/config`. The host
owns authentication and the gateway. Every combat result comes from the engine,
with `headline_total` displayed as the headline. Changes to inputs abort pending
requests and mark previous results for recalculation.

The component obtains champion and item choices, rune schemas, role quest
limits, and patch identity from the backend. Invalid loadouts stay visible so
the user can correct them. Search applies a proposed build only when the backend
sets `is_certified_best` and the user selects Apply.

## Build and check

Use Node 22.18 or later.

```sh
npm ci --prefix ui
npm --prefix ui run typecheck
npm --prefix ui test
npm --prefix ui run build
node ui/build.mjs --check
```

The build writes `static/calculator/calculator.js`, its CSS, and dependency
license comments. The check compares generated bytes without writing them.
`standalone.tsx` and `standalone.css` own the independent page shell and its ten
theme choices. They are excluded from the shared source sync.

Scryglass synchronizes these source files as one hash-bound set:
`Calculator.tsx`, `api.ts`, `types.ts`, and `calculator.css`. The application that
hosts them owns its navigation and theme controls.

## League HUD and rune page

The HUD reads stats from `/api/loadout-stats`, and each champion exposes the engine's default ranks by level. The item shop includes a BIS builder that submits its total gold budget. Uncertified searches show an explicitly labeled candidate only when its event timeline is complete.

`assets/league/README.md` records the patch-specific HUD atlases, sprite coordinates, rune backgrounds, and client CSS. The UI uses versioned remote assets and preserves the source files and hashes here. Rune selections enforce one primary rune per row and two secondary runes from distinct rows. Unimplemented runes remain disabled.
